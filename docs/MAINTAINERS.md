## Review Process

### Documentation Changes
1. **Minor updates** (typos, clarifications) can be merged by any maintainer
2. **Major changes** (new guides, structural changes) require review from primary maintainer
3. **Breaking changes** affecting setup/onboarding require approval from project owner

### PR Requirements
- All documentation PRs must pass CI checks (linting, link checking, spelling)
- Changes to core onboarding docs require manual testing verification
- New documentation should follow established style and structure

## Documentation Standards

### Style Guide
- Use clear, concise language
- Include code examples for technical procedures
- Provide both Windows (PowerShell) and Unix (bash) instructions where applicable
- Use consistent emoji and formatting patterns

### Structure Requirements
- Each major guide should include troubleshooting section
- Cross-reference related documentation
- Include completion checklists for setup procedures
- Maintain table of contents for long documents
