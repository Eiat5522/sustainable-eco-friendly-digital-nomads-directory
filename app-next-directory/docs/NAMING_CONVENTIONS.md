# Naming Conventions

This document outlines the naming conventions adopted for this project to ensure consistency across the codebase.

## JavaScript/TypeScript Naming

### Variables and Functions
- **Use camelCase** for all variables, functions, and object properties
- **Example:**
  ```typescript
  const userName = "John";
  const shortDescription = "A brief description";
  
  function getUserData() {
    return { userId: 123, emailVerified: true };
  }
  ```

### Classes and Components
- **Use PascalCase** for class names and React components
- **Example:**
  ```typescript
  class UserProfile {}
  const UserDashboard: React.FC = () => {};
  ```

### Constants
- **Use UPPER_SNAKE_CASE** for true constants (values that never change)
- **Example:**
  ```typescript
  const API_BASE_URL = "https://api.example.com";
  const MAX_RETRY_ATTEMPTS = 3;
  ```

## GROQ Query Field Naming

When writing GROQ queries for Sanity CMS, use field aliasing to ensure returned JSON keys follow camelCase convention:

### Basic Field Projection
```groq
*[_type == "listing"][0]{
  _id,
  name,
  shortDescription,  // Already camelCase in schema
  longDescription,   // Already camelCase in schema
  "slug": slug.current  // Aliasing for clarity
}
```

### Aliasing for Complex Fields
```groq
*[_type == "city"][0]{
  _id,
  name,
  "slug": slug.current,
  "primaryImage": primaryImage{
    asset->{url}
  },
  "ecoTags": ecoFocusTags[]->name
}
```

### Reserved Sanity Fields
The following Sanity system fields use underscores and are **allowed exceptions**:
- `_id` - Document identifier
- `_type` - Document type
- `_rev` - Document revision
- `_createdAt` - Creation timestamp
- `_updatedAt` - Update timestamp
- `_score` - Search relevance score

## ESLint Configuration

The project enforces camelCase naming through ESLint with the following configuration:

```javascript
"camelcase": ["error", {
  "properties": "never",           // Don't check property names
  "ignoreDestructuring": true,     // Allow destructuring any names
  "ignoreImports": true,           // Allow any import names
  "allow": [
    "^_id$",                       // Sanity document ID
    "^_type$",                     // Sanity document type
    "^_rev$",                      // Sanity revision
    "^_createdAt$",                // Sanity creation date
    "^_updatedAt$",                // Sanity update date
    "^_score$",                    // Search score
    "^unstable_",                  // Next.js experimental APIs
    "^ignored_"                    // Intentionally unused variables
  ]
}]
```

## MongoDB/Mongoose Fields

MongoDB models use camelCase with automatic timestamp fields:

```typescript
interface IUser {
  emailVerified?: Date;
  createdAt: Date;      // Auto-generated by Mongoose
  updatedAt: Date;      // Auto-generated by Mongoose
}
```

## External APIs and Libraries

When interfacing with external APIs or libraries that use snake_case:
1. **Transform at the boundary** - Convert to camelCase when data enters your application
2. **Use type definitions** - Define interfaces with camelCase properties
3. **Map explicitly** - Use explicit mapping functions for clarity

### Example: Transforming External API Data
```typescript
interface ExternalUser {
  user_id: string;
  email_verified: boolean;
}

interface InternalUser {
  userId: string;
  emailVerified: boolean;
}

function transformUser(external: ExternalUser): InternalUser {
  return {
    userId: external.user_id,
    emailVerified: external.email_verified
  };
}
```

## File Naming

- **Components:** PascalCase (e.g., `UserProfile.tsx`, `ListingCard.tsx`)
- **Utilities:** camelCase (e.g., `formatDate.ts`, `validateEmail.ts`)
- **Types:** camelCase (e.g., `user.ts`, `listing.ts`)
- **Tests:** Match source file name with `.test` or `.spec` suffix

## Enforcement

### Automated Checks
1. **ESLint** - Runs on every commit via pre-commit hooks
2. **TypeScript** - Type checking enforces interface naming
3. **CI/CD** - Linting checks run in continuous integration

### Running Checks Locally
```bash
# Run ESLint
npm run lint

# Run type checking
npm run check-types

# Run both
npm run lint && npm run check-types
```

## Migration Guide

If you encounter legacy code with inconsistent naming:

1. **Update GROQ queries** to use field aliases matching camelCase
2. **Update TypeScript interfaces** to use camelCase properties
3. **Run ESLint** to identify remaining violations
4. **Fix violations** one file at a time
5. **Update tests** to match new naming
